# Ellai operational schedule configuration

The quality and follow-up schedulers use `CadenceHours` (4 or 8), `PolicyVersion`, and a positive `ConfigurationRevision`. The default cadence is 4 hours and the default revision is 1. Configuration is scoped by the worker's explicitly configured workspace and organization lists.

Apply the operational schedule configuration revision migration before deploying workers that use it. Deploy the revision-aware worker version to all replicas before increasing a configuration revision: older binaries do not enforce the revision when claiming work. Do not enable new settings until the old workers have drained.

Apply the enrichment provenance migration before deploying the updated Gateway: case timeline reads and classification claims use its tables even when enrichment scheduling is disabled. Jobs created before that migration have no recorded enrichment lease provenance and do not acquire a retrospective timeline entry.

To change a cadence or policy, increase the revision for that role on every replica and apply identical settings. A newer revision waits for any active lease to finish or expire, fences the old lease, and makes the schedule due. A replica with an older revision cannot overwrite or claim the newer schedule. Reusing a revision with different settings produces a mismatch warning and does not run the sweep. A policy version change does not itself prove that every previously processed artifact has been reassessed.

The migration refuses rollback while any schedule has a revision greater than 1. Retain the schedule data and use a forward correction for configuration mistakes.

The classification worker may opt in to discovery of existing running backfill jobs with `CLASSIFICATION_AUTOMATIC_BACKFILL_ENABLED=true`. Discovery is restricted to its configured worker identity, current classification profile, allowed organizations, and active workspace-organization links. The worker processes at most one background item per polling interval using the existing result lease and model semaphore. It can also process manually created running jobs in that same scope. Leave it disabled until that behavior and the background capacity are intended for the deployment.

`Ellai:Operational:Enrichment` is disabled by default. When enabled, it requires the same bounded workspace list, policy version, cadence, and configuration revision as the other operational schedulers. On each due run it creates at most one classification recovery job per active, explicitly allowed organization, with at most `BatchSize` (1 to 100) recent case revisions. Completed or failed classifications with a matching base profile and current translation approval, and pending matching backfill items, are excluded. A due run that finds no work does not retain an empty job. Enable automatic backfill discovery separately to process those jobs. A case timeline shows completed classification work only when a recorded scheduled-job lease produced that exact result; failed, reused, or uncommitted attempts do not claim completion. This is classification recovery, not the complete enrichment role: location resolution, attribution of reused results to every associated case, and reasoning-based follow-up proposals remain outstanding.
