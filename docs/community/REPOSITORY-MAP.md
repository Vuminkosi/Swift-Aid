New session revision snapshots retain the accepted lifecycle action, creator and reviewer identifiers, review time, explicit self-review acknowledgement, and cancellation/completion times. Earlier snapshots lack some or all of these fields and must be treated as unknown rather than backfilled or inferred. A bounded history reader now requires an explicit session-specific authorizer and checks it again after the read. No production authorizer is configured and the HTTP route still returns a generic denial; the staff history view remains unimplemented.

For new published time changes, the revision action is `Rescheduled` and its snapshot retains the previous confirmed UTC start. A draft edit or an equivalent instant with a different offset is recorded as an update. Older snapshots are not rewritten.

The web staff editor keeps an unconfirmed create in page memory with its original session reference and blocks another create until the user checks or explicitly discards it. A successful check requires the same actor, a matching session ID and creator, and current management access, then requests the existing editor tab even if the draft is absent from the public list. An unsaved edit in another session blocks the check. This is not durable offline storage or proof that the currently closed staff authorization gate is operational.

Android now downloads a bounded `text/calendar` response into its app cache and asks the device to open the file; this does not assert that a calendar app imported it. The cached file is retained for the receiving app and remains subject to operating-system cache cleanup. Actual Android calendar-handler behavior remains NOT VERIFIED.

The connected PostgreSQL/TestServer subscription journey covers anonymous public detail, calendar and invitation reads; authenticated consent and idempotent subscription; session revision with renewed consent; cancellation; and unsubscribe. It uses a test principal and a test-only material-eligibility fixture, with session commands invoked directly through the service. It does not prove production staff authorization, actual material approval, provider delivery, browser sign-in, or device behavior.
