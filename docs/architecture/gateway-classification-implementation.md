## First implemented vertical slice

Tables in `swiftaid_classification`: content-addressed `configurations`, leased `results`, immutable case/revision `associations`, notice/configuration `inbox`, ordered metadata `outbox`, and digest-only `quarantine`. Migrations `20261101073125_PersistentClassificationRegistry` and `20261101073438_ClassificationDeliveryFencing` are additive. Database triggers reject completed-result replacement and provenance/configuration changes. The domain's clinical classification is untouched.

Gateway machine routes: `/api/internal/classification/{claim,renew,complete,fail,quarantine}`. Requests are bounded to 32 KiB by Kestrel before endpoint binding. SHA-256-verified bearer credentials, enabled configuration and explicit organization allowlists are required; ordinary cookies do not authorize them. Each request uses a scoped database context. A claim revalidates the committed notice/event identity, active organizational workspace, strict protected journal, configuration and fingerprint. Transient control-plane outages do not authorize ACK. Inference gets at most five attempts by default; renewal cannot extend an attempt beyond ten minutes. No transaction spans inference. Completed/reused and terminal failure states authorize ACK; busy/stale/retry states do not.

Classification lifecycle records publish on `swiftaid.ingestion.v1.classification` through the existing ingestion dispatch loop/stream. This additive outbox lane is needed because the case outbox's foreign key deliberately requires a canonical case event. It has stable message IDs, per-result sequence ordering, lease fencing, eight bounded publication attempts and retained exhaustion. A publication means broker storage, not completed downstream quality/detection.

The Python worker binds an explicitly provisioned durable. Its broker identity has no consumer-create, stream administration or case-publication authority. It has bounded pull lanes and one inference semaphore; token-length-aware batches contain at most four premise/hypothesis pairs and 2,048 padded tokens by default. Source text remains inside the scoped HTTP response and model memory. Reconnect reclaims durable work; a late completion cannot overwrite a newer lease.

## Durable historical backfill

Migration `20261101075637_ClassificationBackfill` adds workspace/organization-scoped `backfills` and `backfill_items`. Starting a caller-identified job snapshots committed `CaseReported`/`CaseReportCorrected` event IDs in one INSERT SELECT; later reports do not move that snapshot. There is no CSV reimport. The existing worker credential must authorize the active workspace/organization, and the creating worker identity owns the job. Repeating the same start does not duplicate items. Configuration changes stop processing with `ConfigurationChanged`; create a new job for an intentional model/taxonomy upgrade.

The worker CLI `--classification-backfill JOB_UUID` uses the same scoped claim, renewal, bounded inference, completion and failure paths as the live consumer. The optional `backfillJobId` on claim is validated against the source snapshot. After registry admission, Gateway binds the item to the **exact source-language configuration/result** selected by that claim, not a loosely matching historical model family. A lost binding/completion reply is recovered by replaying that same source notice. No transaction spans model execution. A separate job process is not proof of GPU capacity for two model instances; deploy only within measured capacity.

Each next-work transaction reconciles at most the first 100 pending items. Only completed or failed persisted results advance outcomes. Counters and item transitions commit atomically and a database constraint enforces `eligible = pending + newlyClassified + reused + abstained + failed`. Indexes support the next pending ordinal. No full-dataset scan occurs for each progress response. `reused` includes already-existing fingerprints and duplicate associations; `newlyClassified` counts non-abstained first associations whose result was created after the job started. These are revision outcomes, not total model attempts. Abstention takes precedence over reuse and remains separately visible. A job may finish with failures; `Completed` means every snapshot item has an outcome, not that every report was classified.

Pause prevents further next-work admission; an already admitted classification may finish. Resume continues the same durable snapshot. The historical CLI runs one paced lane (one-second interval by default, configurable from 0.1 to 60 seconds) rather than globally locking interactive consumers. Busy/retry results retain pending items. Missing protected-source keys, invalid source journals or revoked authority require operator recovery and do not become fabricated success. Full throughput isolation under concurrent application load remains NOT VERIFIED.

Machine routes under `/api/internal/classification`: `POST backfills` with `jobId`, `workspaceId`, `organizationId`; `GET backfills/{id}`; `POST backfills/{id}/next`; `POST backfills/{id}/control` with `paused`. Status is an observable durable checkpoint; next-work reconciles recently completed attempts. No new staff permission or administrative UI is implied by machine endpoints.

PASS: ten PostgreSQL/live tests, including restart with a new DB context, pause/resume, duplicate start, organization denial, snapshot stability and changed configuration. The real pinned-BART/Kestrel/PostgreSQL/JetStream test now adds four isolated source reports and reconciles **4 eligible = 1 newly classified + 2 reused + 1 abstained + 0 failed + 0 pending**. A completed job is readable without an inference implementation. PASS: Python 57 passed, three opt-in broker skips; Ruff and strict mypy passed; EF reports no pending model changes. The live host test caught a `BindAsync` method-name collision with ASP.NET parameter binding; renaming it to `BindResultAsync` fixed startup. ## First deterministic quality checks

`reported-facts-quality-v1` now assesses the immutable facts revision inside Gateway classification admission, before model execution. `quality_assessments` is keyed by source event and rule version; source/case references, report revision, findings and assessment time commit with registry admission. Database triggers reject replacement/deletion. Replaying an older completed inbox without a quality artifact computes the missing assessment without rerunning a completed model result. Existing clinical facts and classifications are untouched.

Checks cover unknown/imprecise occurrence time, missing capture time, exact occurrence after capture/receipt, capture after receipt, imprecise geography, incomplete coordinate pairs, unknown region, unavailable text, repeated normalized observation text within a report, and existing domain animal-count relationships. Legacy context is explicitly unavailable. Timestamp discrepancies are review findings, not rejection or an invented clock-skew limit. Date/range precision is retained; upload time never becomes onset time. No narrative, precise coordinates or patient identifiers are copied into findings. The authenticated classification API and existing Ellai evidence tool return these findings under the same case-read authorization.

## Supersession and imported-case replay correction

Gateway now records `ClassificationSuperseded` once per obsolete result/case/facts-revision association. The cached prediction stays immutable and can still serve another current association. Terminal-notice replay commits supersession instead of rolling the transaction back. A filtered unique index fences concurrent duplicates; the separate full result index remains explicit for all-event outbox ordering.

The integration attempt exposed a pre-existing registration defect: `PostgresCaseRegistrationPersistence` wrote `WorkflowVersion = 0`, while replay initializes it from the first `CaseReported` event (version 1). This made later command replay unavailable. New registration now uses the event version. Migration `RepairInitialCaseWorkflowVersion` repairs only `Reported` cases at aggregate version 2/report revision 1 with exactly the matching initial report/assignment pair and workflow version 0. It does not guess versions for later workflows or alter evidence, outcome, classification or authority. Rollback intentionally retains this data repair. Operators must review the data predicate before deployment; this continuation applied it only to disposable test data.

PASS: 39 PostgreSQL/live tests across classification/backfill, imports, shared-workspace authorization and registration. A synthetic legacy-zero projection was repaired, then a real authorized `ResolveCase` command succeeded. ## Surveillance evaluation loop

The first surveillance slice is restricted to explicitly configured synthetic workspaces and organizations. `Surveillance.Enabled` defaults to false; enabled configuration requires `Mode= SyntheticEvaluation` (without the space), nonempty `Workspaces` and `Organizations`. The hosted worker rejects Production. The method is `reported-area-window-synthetic-v1`: three-day observation-time windows, a 28-day reporting-share baseline, at least three reports and two reporting actors. These are evaluation rules, not validated disease thresholds. Unknown severity remains unknown. Geographic grouping preserves supplied country/region/district/locality identities and never invents coordinates.

PostgreSQL stores work receipts, current derived inputs, versioned assessments, source-revision evidence, signals, officer decisions and publication events. Processing serializes each workspace/organization and commits evidence with the receipt and outbox. Failures retry at most five times. New evidence reopens review while retaining earlier decisions. Existing case-read and protected-review policies authorize every contributing case under authority leases. An unknown actor returns unavailable; database faults still propagate. The existing Ellai classification-evidence tool can include authorized dossiers.

GET `/api/v1/cases/{caseId}/signals`, GET `/api/v1/signals/{signalId}`, and POST `/api/v1/signals/{signalId}/decisions` expose the bounded loop. Decisions require command identity, expected signal version, exact assessment identity and rationale; cookie requests require antiforgery. Verified means officer-reviewed evidence, not outbreak confirmation.

PASS on 2026-11-01: four detector tests and three real PostgreSQL integration scenarios, with zero integration skips after configuring the fixture. The integration scenarios exercise synthetic import/classification outcomes, durable candidate generation, restart/replay, unauthorized reads, idempotent and stale reviews, evidence updates, immutable assessment rejection, and disabled/classifier-absent behavior. The isolated container is `swiftaid-surveillance-test-pg`, loopback port 55440, database `swiftaid_test`. Apply the migrations and the canonical `infra/postgres/case-authority-lock-helper.sql` with dedicated restricted helper/runtime roles before testing. Set `SWIFTAID_RUN_INTAKE_POSTGRES_FIXTURES=1` and `SWIFTAID_TEST_INTAKE_POSTGRES_CONNECTION`, then run the integration project with filter `FullyQualifiedName~SurveillanceLoopTests`. An initial run exposed the unknown-actor exception and passed after its correction.

This slice intentionally caps a workspace/organization at 1,000 derived inputs and authorized dossiers at 32 contributing cases.
