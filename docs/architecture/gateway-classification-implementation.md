# Persistent classification implementation

Baseline: `a64bd6f`, 2026-11-01. Implements the owner-authorized continuation in `designs/data/pipeline-requirements-data-classification.md`. Existing intake, Workspace imports, approvals, protected case journals and PostgreSQL outboxes remain canonical.

## Audit and contract

- Python `jobs/consumer.py` validates envelopes only; the entry point refuses execution. Existing job persistence contracts are not registered as a working repository. They prohibit the legacy Surveillance job type. A classification-specific registry is required; this does not enable that legacy job or change official clinical classification.
- Managed case reports have immutable protected v1/v2 journal events. The Gateway journal reader and payload protection store are reusable. Broker messages contain IDs only, never authorized input or tenant authority.
- Domain outbox rows require case-event foreign keys. Derived intelligence must not masquerade as a case command/event. Classification lifecycle records therefore need an additive outbox lane using the existing dispatch/lease pattern and broker, with no sensitive payload.
- A worker credential is scoped to explicit organizations. Gateway resolves ownership from PostgreSQL, checks active organization/workspace participation and binds each lease to that worker, source event, configuration and fingerprint. There is no direct Python database/case-write access.
- Fingerprints include organization, workspace, sensitivity, normalized source, language, immutable configuration (model revision, taxonomy/labels, preprocessing, hypothesis, inference settings). Conservative scope prevents sharing across authorization domains. Source event references preserve provenance separately from reusable predictions.
- Completed artifacts are immutable. Revision associations preserve older results; only a matching current report revision is current. Administrative events do not create new classifiable content.
- Pull consumers use explicit ACK only after Gateway confirms a persisted terminal outcome or completed cache reuse. Transient control-plane failures remain unacknowledged. Lease expiry fences old completion; bounded retries produce durable failure. Invalid broker data is quarantined by digest/stream sequence without retaining raw payload.

## Acceptance and dependencies

First deliver registry + scoped claim/complete/fail + bounded Python consumer and pinned BART inference. Test duplicate delivery, concurrent cache misses, expired completion, changed configuration, cross-organization denial, retry exhaustion and result-before-ACK. Then implement backfill/read tools and downstream quality/detection/signal/investigation stages. Keep canonical documents current and commit verified slices.

The historical 15,000-row benchmark database was explicitly disposable and removed after its tests. Do not describe it as retained production data or silently repopulate the shared database. Backfill must enumerate available durable source revisions and report actual counts.

Model source: [facebook/bart-large-mnli](https://huggingface.co/facebook/bart-large-mnli), pinned revision `d7645e127eaf1aefc7862fd59a17a5aa8558b8ce` verified from the repository API. Its semantic scores are not calibrated clinical probabilities. English-only inference is the initial supported profile; unknown/Shona/siSwati require explicit abstention until independently labeled evaluation approves a language path. Hierarchical pruning and inferred clinical urgency are not enabled. Local GPU observed: RTX 5050 Laptop, 8 GiB; this is inventory, not inference capacity proof.

Rollout remains opt-in; no shared Gateway restart/migration is implied. No diagnosis, official classification, outbreak confirmation or consequential action is authorized by a model output. Human review and existing approvals remain separate.

## First implemented vertical slice

Tables in `swiftaid_classification`: content-addressed `configurations`, leased `results`, immutable case/revision `associations`, notice/configuration `inbox`, ordered metadata `outbox`, and digest-only `quarantine`. Migrations `20261101073125_PersistentClassificationRegistry` and `20261101073438_ClassificationDeliveryFencing` are additive. Database triggers reject completed-result replacement and provenance/configuration changes. The domain's clinical classification is untouched.

Gateway machine routes: `/api/internal/classification/{claim,renew,complete,fail,quarantine}`. Requests are bounded to 32 KiB by Kestrel before endpoint binding. SHA-256-verified bearer credentials, enabled configuration and explicit organization allowlists are required; ordinary cookies do not authorize them. Each request uses a scoped database context. A claim revalidates the committed notice/event identity, active organizational workspace, strict protected journal, configuration and fingerprint. Transient control-plane outages do not authorize ACK. Inference gets at most five attempts by default; renewal cannot extend an attempt beyond ten minutes. No transaction spans inference. Completed/reused and terminal failure states authorize ACK; busy/stale/retry states do not.

Classification lifecycle records publish on `swiftaid.ingestion.v1.classification` through the existing ingestion dispatch loop/stream. This additive outbox lane is needed because the case outbox's foreign key deliberately requires a canonical case event. It has stable message IDs, per-result sequence ordering, lease fencing, eight bounded publication attempts and retained exhaustion. A publication means broker storage, not completed downstream quality/detection.

The Python worker binds an explicitly provisioned durable. Its broker identity has no consumer-create, stream administration or case-publication authority. It has bounded pull lanes and one inference semaphore; token-length-aware batches contain at most four premise/hypothesis pairs and 2,048 padded tokens by default. Source text remains inside the scoped HTTP response and model memory. Reconnect reclaims durable work; a late completion cannot overwrite a newer lease.

Declared language takes precedence over any corpus fallback; `nd` is retained as Ndebele metadata and also abstains. Corrections without language provenance use the configured fallback (default `und`), never a guessed language. No source text or decrypted row is stored in the classification registry. The original language remains in immutable protected import evidence.

They return at most ten configurations for the current facts revision, label definitions/raw scores, source event references, configuration-currentness and observable failures/abstention. No inference, lease token, source narrative or another case's association is exposed. Historical configurations are explicitly distinguished from the active profile. Public-help tool allowlists and budgets still apply.

## Durable historical backfill

Migration `20261101075637_ClassificationBackfill` adds workspace/organization-scoped `backfills` and `backfill_items`. Starting a caller-identified job snapshots committed `CaseReported`/`CaseReportCorrected` event IDs in one INSERT SELECT; later reports do not move that snapshot. There is no CSV reimport. The existing worker credential must authorize the active workspace/organization, and the creating worker identity owns the job. Repeating the same start does not duplicate items. Configuration changes stop processing with `ConfigurationChanged`; create a new job for an intentional model/taxonomy upgrade.

The worker CLI `--classification-backfill JOB_UUID` uses the same scoped claim, renewal, bounded inference, completion and failure paths as the live consumer. The optional `backfillJobId` on claim is validated against the source snapshot. After registry admission, Gateway binds the item to the **exact source-language configuration/result** selected by that claim, not a loosely matching historical model family. A lost binding/completion reply is recovered by replaying that same source notice. No transaction spans model execution. A separate job process is not proof of GPU capacity for two model instances; deploy only within measured capacity.

Each next-work transaction reconciles at most the first 100 pending items. Only completed or failed persisted results advance outcomes. Counters and item transitions commit atomically and a database constraint enforces `eligible = pending + newlyClassified + reused + abstained + failed`. Indexes support the next pending ordinal. No full-dataset scan occurs for each progress response. `reused` includes already-existing fingerprints and duplicate associations; `newlyClassified` counts non-abstained first associations whose result was created after the job started. These are revision outcomes, not total model attempts. Abstention takes precedence over reuse and remains separately visible. A job may finish with failures; `Completed` means every snapshot item has an outcome, not that every report was classified.

Pause prevents further next-work admission; an already admitted classification may finish. Resume continues the same durable snapshot. The historical CLI runs one paced lane (one-second interval by default, configurable from 0.1 to 60 seconds) rather than globally locking interactive consumers. Busy/retry results retain pending items. Missing protected-source keys, invalid source journals or revoked authority require operator recovery and do not become fabricated success. Full throughput isolation under concurrent application load remains NOT VERIFIED.

Machine routes under `/api/internal/classification`: `POST backfills` with `jobId`, `workspaceId`, `organizationId`; `GET backfills/{id}`; `POST backfills/{id}/next`; `POST backfills/{id}/control` with `paused`. Status is an observable durable checkpoint; next-work reconciles recently completed attempts. No new staff permission or administrative UI is implied by machine endpoints.

PASS: ten PostgreSQL/live tests, including restart with a new DB context, pause/resume, duplicate start, organization denial, snapshot stability and changed configuration. The real pinned-BART/Kestrel/PostgreSQL/JetStream test now adds four isolated source reports and reconciles **4 eligible = 1 newly classified + 2 reused + 1 abstained + 0 failed + 0 pending**. A completed job is readable without an inference implementation. PASS: Python 57 passed, three opt-in broker skips; Ruff and strict mypy passed; EF reports no pending model changes. The live host test caught a `BindAsync` method-name collision with ASP.NET parameter binding; renaming it to `BindResultAsync` fixed startup. An older broad-workspace fixture exceeded the bounded reconciliation page; isolating its source workspace fixed the test without expanding production bounds.

NOT VERIFIED: historical 15k backfill (the earlier benchmark DB was removed), 100k/million pipeline, GPU profile, full worker-process termination during inference, role-restricted deployment of the new tables, concurrent interactive workload, downstream quality/detection/correlation/investigation and operational dashboards. The shared Gateway has not been recreated or migrated by this slice.

## First deterministic quality checks

`reported-facts-quality-v1` now assesses the immutable facts revision inside Gateway classification admission, before model execution. `quality_assessments` is keyed by source event and rule version; source/case references, report revision, findings and assessment time commit with registry admission. Database triggers reject replacement/deletion. Replaying an older completed inbox without a quality artifact computes the missing assessment without rerunning a completed model result. Existing clinical facts and classifications are untouched.

Checks cover unknown/imprecise occurrence time, missing capture time, exact occurrence after capture/receipt, capture after receipt, imprecise geography, incomplete coordinate pairs, unknown region, unavailable text, repeated normalized observation text within a report, and existing domain animal-count relationships. Legacy context is explicitly unavailable. Timestamp discrepancies are review findings, not rejection or an invented clock-skew limit. Date/range precision is retained; upload time never becomes onset time. No narrative, precise coordinates or patient identifiers are copied into findings. The authenticated classification API and existing Ellai evidence tool return these findings under the same case-read authorization.

PASS: ten PostgreSQL/live classification tests including durable quality, authorized reads and rejection of direct assessment updates; 303 application/Ellai/quality tests passed with three provider skips. The database immutability regression failed before its enforcement migration and passed afterward. Migrations are additive: `20261101080633_ReportQualityAssessment` and `20261101080726_ImmutableReportQuality`.

This is a bounded quality slice, not completion of semantic quality or surveillance: cross-report duplicate/entity reconciliation, contradictory revision analysis, extraction-confidence calibration, independent quality scheduling, PostGIS detection, signal correlation, verification and investigation orchestration remain outstanding. A rule change requires a new version rather than overwriting old findings.
