# Ellai client voice processing progress

This checklist tracks implementation against [`ellai-client-voice-processing.md`](../designs/ellai/ellai-client-voice-processing.md). It is an execution record, not a completion claim. Updated 2026-10-31 against baseline `f87b1947e28826bc6978bbb76cf79e5a0eae5eaf`.

## Existing pipeline audit

| Area | Current implementation | Classification | Evidence / open work |
|---|---|---|---|
| Web and MAUI microphone capture | Web uses shared `SwiftAid.UI/wwwroot/js/ellai-voice-capture.js`; Android and iOS live dialogs use platform implementations of `IEllaiNativeVoiceCapture`. iOS falls back to WebView capture if native startup fails and browser capture is available. | REFACTOR | Web requests browser AEC/noise/gain processing and reports effective settings. Android and iOS live capture emit transient mono PCM16 at 24 kHz into the same bounded Gateway stream; browser and device behavior remains NOT VERIFIED. |
| Client speech boundary detection | Client RMS thresholds, fixed silence duration and an automatic `OnVoiceTurnEnded` callback. | REMOVE | Removed acoustic auto-finalization. Live capture now ends on explicit user stop; final utterance remains determined by the configured ASR result. |
| PCM resampling/chunking | Shared JavaScript conversion to bounded 24 kHz mono signed 16-bit samples, then .NET interop into a bounded channel-backed stream. | REUSE / REFACTOR | Format and existing voice endpoint are preserved. The interop queue and channel apply backpressure; the server consumes chunks as they arrive. Browser and physical-device runtime behavior remains NOT VERIFIED. |
| Transcription | Gateway-owned Meta upload/realtime adapters behind consent and session checks. Live capture streams on the existing voice route; recorded capture remains a bounded upload. | REUSE / REFACTOR | Gateway Blazor uses the in-process stream path and MAUI uses authenticated `StreamContent`. The realtime adapter forwards bounded partial events to the active session coordinator for display only; only provider-final text is returned for submission. A local WebSocket integration test proves ordered PCM and partial/final behavior; real provider, browser and device behavior remains NOT VERIFIED. |
| Client live-stream recovery | Shared Web/MAUI host keeps a bounded, transient PCM copy (up to 32 MiB). Stream loss, browser/WebView offline events, or 500 ms channel backpressure switch capture to memory. On restored connectivity, one bounded reconnect starts a fresh stream epoch, replays ordered PCM, and resumes live forwarding; failure retains the single upload fallback on Stop. Browser capture-queue overflow stops capture and recovers the buffered turn. | IMPLEMENTED; NETWORK AND RUNTIME VALIDATION OPEN | Transcript submission remains on the existing single `OnSend` path. Failed recovery says the turn was not sent; PCM is cleared after processing or cancellation and is not persisted. Real browser/WebView/device connectivity transitions, physical provider reconnect behavior, and long-duration memory impact remain NOT VERIFIED. |
| Transcript normalization | Legacy `TranscriptTurnNormalizer` drops partial/speech-end events and deduplicates final provider turns by epoch. | REMOVE FROM ACTIVE PATH | The active flow uses the realtime adapter's final collector and the coordinator's stream epoch/provider-turn fences. Partials are stored only as one bounded transient display value in the active session state and are cleared on matching final, stream end, cancellation, recovery or a newer epoch. |
| Gateway VAD | `SileroOnnxVoiceActivityDetector` loads the upstream pinned 16 kHz opset-15 model once and creates independent recurrent state/context per detector session. `SileroVoiceActivityAudioStream` decodes bounded PCM16 batches, resamples across chunk boundaries, and emits ordered 512-sample inference frames. Live ASR and VAD consume the same incoming stream concurrently while ASR preserves the original bytes. | IMPLEMENTED; TURN-FLOW VALIDATION OPEN | The actual model, silence, recurrent isolation, sequence-gap reset, 24 kHz resampling, source-rate reset and live-service fan-out run in integration tests. Ordered VAD speech/silence activity feeds the per-session turn coordinator; concurrent end-to-end resource and lifecycle validation remains open. |
| Turn coordination | `EllaiVoiceTurnCoordinator` maintains a per-session live-stream epoch, ordered VAD speech/silence states, provider-final deduplication, response playback identity, and a confirmed barge-in decision. | REFACTOR | The Gateway feeds 16 kHz Silero results and provider partial/final events into the coordinator. Owner-scoped authenticated and guest status routes expose no-store turn state and the latest bounded partial to the shared web/MAUI UI. UI partial text is rendered separately from the editable draft and never submitted. Silence only creates an endpoint candidate; the provider-final transcript remains authoritative. Linguistic continuation semantics remain open. |

Turn coordinator thresholds can be configured through `Ellai:VoiceTurn:SpeechStartConfirmationMs`, `Ellai:VoiceTurn:EndOfTurnSilenceMs`, `Ellai:VoiceTurn:BargeInConfirmationMs`, and `Ellai:VoiceTurn:MaximumTurnDurationMs`. Defaults are 120 ms, 650 ms, 180 ms, and 480,000 ms (eight minutes); Gateway startup rejects values outside the coordinator bounds. Realtime Gateway transcription cancels at the configured duration, returns no transcript, clears transient partial text, and places the turn in `Recovering`. A live turn with no accepted final transcript also enters recovery; the shared UI polls owner-scoped status, and the next stream returns the session to `Listening`.

The coordinator exposes `System.Diagnostics.Metrics` measurements for speech-start confirmation, endpoint silence, barge-in confirmation, accepted-final latency, and recovery counts through meter `SwiftAid.Application.Ellai.Voice`. Measurements have no session, transcript, or audio dimensions. The Gateway has no configured OpenTelemetry exporter in this checkout, so metric collection/export is NOT VERIFIED.
| Native Android capture processing | Guest evidence uses `MediaRecorder`/AAC in `AndroidAudioCaptureService`; Ellai live dialog uses dedicated `AudioRecord` with `VOICE_COMMUNICATION`, 24 kHz capture (48 kHz fallback), per-session AEC/noise suppression/AGC when available, audio focus, route-change notification, and stop-on-background lifecycle handling. Native Ellai playback uses voice-communication audio usage. | IMPLEMENTED; DEVICE VALIDATION OPEN | The Android app permission and consent still precede capture; audio remains transient and feeds the same bounded Gateway PCM stream. Android source build passes. Hardware effect activation, Bluetooth/wired/speaker routing, acoustic quality, and interruption behavior remain NOT VERIFIED on a device. |
| iOS capture processing | `IosEllaiNativeVoiceCapture` configures `AVAudioSession` for `PlayAndRecord`/`VoiceChat`, enables `AVAudioEngine` voice processing when supported, converts bounded float frames to 24 kHz mono PCM16, and restores the prior category/mode. Route changes are reported; interruptions, input loss, and app backgrounding stop and discard the active turn. | IMPLEMENTED; DEVICE VALIDATION OPEN | The service is registered only for iOS MAUI and uses the shared native capture interface/transport. PCM conversion has deterministic unit coverage. The iOS target reached C# compilation, but packaging failed because cached GoogleDataTransport framework resources are missing; real route, processing, interruption and lifecycle behavior remains NOT VERIFIED. |
| Client playback | Web Audio PCM player and native Android `AudioTrack` player consume Gateway PCM; active response streams are identified by session, response sequence and random playback ID. | REUSE / REFACTOR | Stop aborts local playback and requests cancellation of the matching Gateway synthesis/copy stream. Browser RMS and Gateway Silero activity independently confirm barge-in for 180 ms when browser echo cancellation is reported enabled; incoming capture continues and a stale ASR epoch is discarded. Device/browser stop latency, false-positive behavior and echo suppression are NOT VERIFIED. |
| Synthesis | Gateway synthesis boundary and bounded PCM routes exist. Product `SA-ELV-08` gates exact checkpoint deployment on confirmed rights. | REUSE; DEPLOYMENT GATED | Do not download/package model weights or claim a generally enabled production voice without the exact rights and deployment evidence. |

- [ ] Phase B: validate iOS voice processing, Bluetooth/wired routes, interruption handling, and lifecycle recovery on physical devices.
- [x] Phase C (partial): pin the upstream MIT Silero 16 kHz opset-15 model and ONNX Runtime dependency; validate the actual model tensor contract, per-session state isolation, gap reset, strict frame ordering and bounded frame size.
- [x] Phase C (partial): stream PCM from capture through the existing client/Gateway route and process it concurrently with VAD and realtime ASR through bounded channels; preserve exact provider audio and continue ASR if VAD fails.
- [ ] Phase C: validate inference bounds and per-session lifecycle under concurrent end-to-end streams.
- [x] Phase D (partial): add deterministic listening, speech candidate, user speaking, endpoint candidate, processing, assistant speaking, interrupted and recovering states; VAD timing, bounded display-only provider partials, provider-final deduplication, configurable maximum turn duration, recovery feedback and per-session live-stream epochs are covered. Linguistic continuation and durable turn events remain open.
- [x] Phase E (partial): keep live capture/transcription active during response playback; after 180 ms of local RMS and/or Gateway Silero speech activity, stop that exact playback and keep receiving the utterance. A newer stream cancels the prior epoch and late provider finals are rejected. Client/server barge-in coordination is covered in focused integration tests; device/browser latency and false-positive behavior remain NOT VERIFIED.
- [x] Phase F (partial): implement bounded live client-to-Gateway streaming for shared Web/MAUI capture with ordered PCM and transport backpressure; retain the configured upload fallback.
- [x] Phase F (partial): preserve live PCM in a bounded transient buffer after stream loss/backpressure and make at most one upload recovery attempt when capture stops; one transcript follows the existing submit path exactly once.
- [x] Phase F (partial): observe browser/WebView online/offline events, capture live turns in memory while offline, and clearly report that a restored network signal leaves the turn buffered until stop.
- [ ] Phase F: verify real browser/WebView/device network transitions and stream epochs. Continuous stream reattachment and a persistent offline queue remain open; this implementation only offers one stop-time upload attempt.
- [ ] Phase G: deterministic audio/turn/concurrency/safety tests, browser and Android Release fixture parity, accessible UI journeys, documentation and evidence-gated cleanup.
