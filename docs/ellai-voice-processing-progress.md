Live ASR and VAD consume the same incoming stream concurrently while ASR preserves the original bytes. | IMPLEMENTED; NOT YET IN TURN FLOW | The actual model, silence, recurrent isolation, sequence-gap reset, 24 kHz resampling, source-rate reset and live-service fan-out run in integration tests. VAD activity results are not yet combined with ASR events by a turn coordinator. |
| Turn coordination | `EllaiVoiceTurnCoordinator` maintains a per-session live-stream epoch, ordered VAD speech/silence states, provider-final deduplication, response playback identity, and a confirmed barge-in decision. | REFACTOR | The Gateway feeds 16 kHz Silero results and provider-final ASR turns into the coordinator. Silence only creates an endpoint candidate; the provider-final transcript is still required before the voice result can be submitted. The current provider adapter does not expose live partial events or continuation semantics. |

Turn coordinator thresholds can be configured through `Ellai:VoiceTurn:SpeechStartConfirmationMs`, `Ellai:VoiceTurn:EndOfTurnSilenceMs`, and `Ellai:VoiceTurn:BargeInConfirmationMs`. Defaults remain 120 ms, 650 ms, and 180 ms; Gateway startup rejects values outside the documented coordinator bounds. A live turn with no accepted final transcript now enters `Recovering`, and the next stream returns the session to `Listening`; a UI recovery-state feed remains open.
| Native Android capture processing | Original guest evidence recording uses `MediaRecorder`/AAC in `AndroidAudioCaptureService`; Ellai conversational capture uses the shared WebView module. | REUSE / REFACTOR | Do not conflate original evidence capture with conversational audio. `AcousticEchoCanceler`, `NoiseSuppressor`, `AutomaticGainControl`, voice-communication routing, audio focus, and Bluetooth/lifecycle handling are NOT VERIFIED for Ellai. |
| iOS capture processing | Ellai conversational capture uses the shared WebView module; no Ellai-specific `AVAudioSession`/voice-processing engine was found. | NOT VERIFIED | Physical iOS audio processing, route changes, interruptions and lifecycle restoration are NOT VERIFIED. |
| Client playback | Web Audio PCM player and native Android `AudioTrack` player consume Gateway PCM; active response streams are identified by session, response sequence and random playback ID. | REUSE / REFACTOR | Stop aborts local playback and requests cancellation of the matching Gateway synthesis/copy stream. Browser RMS and Gateway Silero activity independently confirm barge-in for 180 ms when browser echo cancellation is reported enabled; incoming capture continues and a stale ASR epoch is discarded. Device/browser stop latency, false-positive behavior and echo suppression are NOT VERIFIED. |
| Synthesis | Gateway synthesis boundary and bounded PCM routes exist. Product `SA-ELV-08` gates exact checkpoint deployment on confirmed rights. | REUSE; DEPLOYMENT GATED | Do not download/package model weights or claim a generally enabled production voice without the exact rights and deployment evidence. |

## Progress checklist

- [x] Phase A: inspect current client capture, PCM, transcription, playback, gateway transcription/synthesis and existing turn helpers.
- [x] Phase B (partial): switch shared web/MAUI capture from `ScriptProcessorNode` to `AudioWorklet`; preserve 24 kHz mono PCM and expose browser processing status.
- [x] Phase B (partial): show the browser/WebView-reported AEC, noise suppression and gain-control settings in the active capture status; actual effective behavior remains runtime-dependent and NOT VERIFIED.
- [x] Phase B (partial): bound the JS-to-.NET audio queue and discard incomplete captures on transport backpressure or no-speech timeout.
- [ ] Phase A: record baseline measurements for capture-to-final, final-to-response, first audio, stop latency, underruns, resource use and continuity.
- [ ] Phase B: native Android voice-communication capture and platform echo/noise/gain effects, route/focus changes and lifecycle recovery.
- [ ] Phase B: iOS audio session and voice-processing capability, route/focus changes and lifecycle recovery.
- [x] Phase C (partial): pin the upstream MIT Silero 16 kHz opset-15 model and ONNX Runtime dependency; validate the actual model tensor contract, per-session state isolation, gap reset, strict frame ordering and bounded frame size.
- [x] Phase C (partial): stream PCM from capture through the existing client/Gateway route and process it concurrently with VAD and realtime ASR through bounded channels; preserve exact provider audio and continue ASR if VAD fails.
- [ ] Phase C: validate inference bounds and per-session lifecycle under concurrent end-to-end streams.
- [x] Phase D (partial): add deterministic listening, speech candidate, user speaking, endpoint candidate, processing, assistant speaking and interrupted states; VAD timing, provider-final deduplication and per-session live-stream epochs are covered. Live ASR partials, linguistic continuation, recovery UX and durable turn events remain open.
- [x] Phase E (partial): keep live capture/transcription active during response playback; after 180 ms of local RMS and/or Gateway Silero speech activity, stop that exact playback and keep receiving the utterance. A newer stream cancels the prior epoch and late provider finals are rejected. Client/server barge-in coordination is covered in focused integration tests; device/browser latency and false-positive behavior remain NOT VERIFIED.
- [x] Phase F (partial): implement bounded live client-to-Gateway streaming for shared Web/MAUI capture with ordered PCM and transport backpressure; retain the configured upload fallback.
- [ ] Phase F: verify reconnect/epoch behavior, no repeated tool effects, offline transitions and client/device streaming behavior.
- [ ] Phase G: deterministic audio/turn/concurrency/safety tests, browser and Android Release fixture parity, accessible UI journeys, documentation and evidence-gated cleanup.
